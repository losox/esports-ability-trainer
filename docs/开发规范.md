# 开发规范

> 当进入开发阶段（写代码）时，必须阅读本文档并遵从。

---

## 一、编码规则

### TypeScript / JavaScript

1. **严格模式**：`tsconfig.json` 中 `"strict": true`，不允许 `any`，确需使用时加注释说明原因
2. **命名**：变量/函数 camelCase；类/接口/类型 PascalCase；常量 UPPER_SNAKE_CASE；文件名 kebab-case
3. **函数**：单个函数不超过 50 行，超过则拆分
4. **类型**：所有函数参数和返回值显式标注类型，不依赖类型推断
5. **错误处理**：仅在系统边界（用户输入、外部API）做 try-catch，内部代码信任类型系统
6. **导入**：使用 ES Module 标准导入，禁用 `require()`
7. **禁止**：不使用 `var`，不用 `==`（用 `===`），不修改函数参数

### React 组件

1. **函数组件**：全部使用函数组件 + Hooks，不用 class 组件
2. **Props**：必须定义 TypeScript 接口，禁止 `props: any`
3. **副作用**：`useEffect` 必须有清理逻辑（如有副作用），依赖数组必须完整
4. **状态**：简单状态用 `useState`/`useReducer`，跨组件用 Zustand，不用 Context 做状态管理（Context 仅做依赖注入）
5. **渲染**：不在 render 中做副作用，不计算派生状态用 `useMemo`
6. **key**：列表渲染必须用稳定唯一 key，禁止用数组索引
7. **组件大小**：单组件 JSX 不超过 150 行，超过则拆分子组件

### Astro 页面

1. **静态优先**：营销页面（首页/关于/帮助）必须 SSG，零客户端 JS
2. **岛屿**：交互组件用 `client:load` 或 `client:visible` 指令，按需加载
3. **Three.js 岛屿**：3D 模块用 `client:only="react"`，不在服务端渲染
4. **SEO**：每页必须有 `title`、`description`、`hreflang` 标签
5. **多语言**：每个页面必须有 `/en/` 和 `/zh/` 两个版本，内容同步

### Three.js 3D 场景

1. **场景结构**：每个训练模块继承共享 `SceneBase`，复用渲染循环、灯光、摄像机设置
2. **内存管理**：场景切换时必须 `dispose()` 几何体、材质、纹理，防止内存泄漏
3. **性能**：目标帧率 60fps，用 `requestAnimationFrame`，不用 `setInterval` 做渲染循环
4. **对象池**：频繁创建/销毁的对象（如靶子、球）用对象池，不反复 new/dispose
5. **HUD**：用 DOM 覆盖层，不用 Three.js 内置文字（性能差）
6. **Pointer Lock**：FPS 模块用 Pointer Lock API，退出时必须释放锁定
7. **灵敏度**：从用户设置读取灵敏度参数，乘入鼠标移动计算

## 二、代码审查清单（每次提交前自检）

### 必查项

- [ ] TypeScript 类型检查通过（`tsc --noEmit` 无报错）
- [ ] ESLint 检查通过（无 error，warning 已处理或注明原因）
- [ ] 无 `console.log` 残留（调试用的已清除）
- [ ] 无硬编码的 API 密钥、URL、敏感信息
- [ ] 无 `any` 类型（确需使用的已加注释）
- [ ] 函数/组件大小未超限
- [ ] 新增依赖是否必要（能否用已有依赖实现）

### 逻辑检查

- [ ] 边界条件已处理（空数组、null、undefined、0）
- [ ] 异步操作有错误处理
- [ ] 事件监听器有对应的清理（removeEventListener / dispose）
- [ ] Three.js 对象有 dispose 调用
- [ ] React useEffect 有清理函数

### 多语言检查

- [ ] 新增的文案已加入 `en.json` 和 `zh.json`
- [ ] 两语言文案内容一致
- [ ] 无硬编码中/英文字符串（全部走 i18n）

### 安全检查

- [ ] 用户输入有校验和转义
- [ ] SQL 查询用参数化（Supabase SDK 自带，但 Edge Function 中手写 SQL 要注意）
- [ ] 无 `dangerouslySetInnerHTML`（确需使用时已做净化）
- [ ] Supabase RLS 策略已配置（新表必须有行级安全）

## 三、安全规则

1. **密钥管理**：所有密钥（Supabase URL/Key、第三方API）放 `.env.local`，`.gitignore` 中排除
2. **密钥检测**：pre-commit 钩子扫描代码中是否包含 key/token/secret 模式，发现即阻止提交
3. **RLS 策略**：每张表必须有 Row Level Security，默认拒绝，按角色开放
4. **输入校验**：前端 + Edge Function 双重校验用户输入
5. **CORS**：Supabase 默认配置，不自定义放宽
6. **依赖安全**：每月跑 `npm audit`，高危漏洞立即修

## 四、反模式清单（禁止行为）

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| 静默执行 | 构建或测试中不沟通 | 每步操作前说明意图，结果出来后报告 |
| 不确认就部署 | 直接部署到生产 | 部署前必须用户确认 |
| 跳过测试 | 先写代码后补测试 | 先写测试再写实现（TDD） |
| 过度设计 | 加未来可能用到的功能 | 只做当前需求，不过度抽象 |
| 重复代码 | 三处以上相同逻辑 | 抽取共享函数/组件 |
| 长函数 | 超过50行的函数 | 拆分为小函数 |
| 魔法数字 | 代码中直接写数字 | 提取为常量，命名说明含义 |
| 提交密钥 | 代码中包含API key | 放 .env.local，git ignore |
| 不同步多语言 | 只改了一种语言 | 两语言必须同步修改 |
| 忽略 dispose | Three.js 对象不清理 | 场景切换时必须 dispose |
| 提交前不自检 | 直接 git add/commit | 先跑审查清单，再提交 |
| 破坏性操作不确认 | git reset --hard / 删除文件 | 必须用户确认后执行 |
